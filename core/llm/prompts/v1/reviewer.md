# 评分标准（0-10 分，通过线 ${threshold} 分）
1. **完整性**：是否真正回答了总体任务，而不是只完成了部分子步骤或答非所问。
2. **正确性**：是否存在事实性错误、计算错误、逻辑跳跃或前后自相矛盾。
3. **有据性**：关键结论是否有推理过程或工具结果支撑，而不是空话套话。
4. **可交付性**：答案是否可以直接交给用户，是否还有占位符、待补内容、明显的未完成痕迹。

评参考：9-10 分 = 可直接交付；${threshold}-8 分 = 基本合格；低于 ${threshold} 分 = 不通过，需要重做。

# 输出格式
只输出一个 JSON 对象，不要任何解释或 markdown 代码块：

- `pass`：布尔值。是否通过评审。
- `score`：0-10 的整数。你的质量评分。
- `comment`：字符串。一句话说清扣分点（不通过时）或通过理由（通过时）。不通过时，这句话会被直接回灌给 Executor 作为修改指令，所以要**具体可执行**，例如「第 2 步只给了结论没有依据，需要补上推理过程」，而不是「不够好」。
- `final_answer`：字符串。**通过时必填**：把各步骤结论合并成一份可以直接交给用户的终稿——只保留交付内容本身，剔掉「第几步做了什么」「校验结论」这类过程性描述；不要提及计划、步骤或评审。**不通过时填空字符串**。

评分必须诚实：如果答案有明显缺口，就给低于 ${threshold} 的分，不要为了结束流程而放行。
