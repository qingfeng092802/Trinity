## 0. 一页结论

| 问题 | 答案 | 最硬的那条证据 |
|---|---|---|
| 哪个检索组件真有收益？ | **只有精排** | nDCG@5 0.9586 → **0.9952（+3.66pp）**，原始 p=**0.000473** ⇒ 42 元族校正后 **0.0199 ✓**；15 个非零对**全同号、零回归** |
| 混合检索一定比单路好？ | **在中文百科语料上不成立** | 纯 BM25 0.9654 **> 混合 0.9586**；纯向量 0.9170 是全场另一条过校正的结论（**−4.17pp，p=0.0130 ✓**） |

| 换更大 embedding 划算吗？ | **不划算** | base +1.08pp / large +1.00pp（均 **n.s.**），P95 41 → 86 → **309 ms**，large 一组索引重建独占 21.9 min |
| 分块策略能消融吗？ | **本语料上结构不可测**（两次实跑均确认） | heading/fixed/semantic 与基线 **0 个非零对**、四指标逐位相同（1,000 篇全单段落、p50 411 字 < chunk_size 500） |
| 换运行时（torch ↔ ONNX）会影响结果吗？ | **不会，逐位一致** | 210 道计分题 top-5 顺序与四指标全等、**0 非零对** ⇒ 量化/换运行时是纯工程收益 |
| 检索层能自己拒答吗？ | **一次都没有** | 90 道库外题，检索层 **90/90（100%）** 照样返回 4–5 篇材料 |
| 融合超参要调吗？ | 不敏感，不值得单列表 | `rrf_k` 三档（20/60/100）极差只有 **0.24pp**（相对 k=60 是 +0.06 / −0.18pp，全 **n.s.**）；`fetch_k` 20→50 反而**多 3 道未召回** |

**选型建议（每条都指向上面的数字）**

| 场景 | 建议 | 理由 |
|---|---|---|
| 中文百科/新闻类语料、延迟敏感 | **BM25 为主，向量只做召回补充、不给融合权重** | 向量臂是唯一被证实显著的**负**效应；BM25 单独用还略胜混合 |
| 术语/编号密集、可容忍慢（规程、合同、医疗） | **上精排，检索 P95 预算给到 ~11 s** | +3.66pp nDCG、零副作用；术语题 nDCG@5 直接 **1.0000（45/45 首槽）** |
| 必须能拒答 | 精排 + 专门的拒答 prompt，**别指望检索层** | 检索层对库外题 100% 返回材料 ⇒ 拒答只能发生在生成侧 |
| 长文档、多级标题 | **先补语料再谈分块** | 分块三臂在本语料上 0 非零对，"分块无影响"这种结论在此不可证伪 |

## 3. 组件读数

1. **精排是唯一改变失败结构的组件**：n=100 与 n=300 两趟都是 +3pp 以上，且**没引入一道新错误**
   （`F4 只本臂失 = 0`，§4）。n=100 是 +6.31pp、n=300 是 +3.66pp —— 缩水不是效应衰减，
   是 300 题趟的基线本身高了 3.6pp（0.9226 → 0.9586，见 §6）。
2. **v2-m3 该砍**：n=100 与 base 三列指标**逐位相同**（0.9857/0.9857/0.9857），P95 39 868 vs 12 468 ms（×3.2）。
   ⇒ 重排模型的大小在这份语料上完全不买精度。
3. **融合**：`bm25_only` 0.9654 > `weighted(0.4:0.6)` 0.9586 > `rrf` 0.9570 ≫ `vector_only` 0.9170。
   只有向量那条显著。`bm25_only` 那 +0.67pp 有 **23 个非零对**（理论下界 2.4e-07，绰绰有余）
   却实测原始 p=0.4577 ⇒ 这是**真的没效应**，不是样本不够；RRF 与 weighted 的差异同理。
4. **嵌入后端**：ONNX ↔ torch 同权重 **210 题 top-5 逐位一致、0 非零对**，P95 39.5 vs 41.2 ms。
   ⇒ "换运行时是纯工程收益"有硬证据；任何"ONNX 化后精度变了"的说法在这条上口径就错了。
5. **嵌入模型大小**：small → base +1.08pp → large +1.00pp（**加大反而略降**），P95 41 → 86 → 309 ms。
   ⇒ 对外材料与报表里**不许**写"换更大 embedding 提升 X pp"。
6. **分块**：三条臂与基线完全同分且 0 非零对。原因不是"分块不重要"，而是这份语料**没有可分的结构**
   （100% 单段落、无标题、p50 411 字 < chunk_size 500 token 档）。真正被切开的只有 `chunk_size=256`
   （+0.13pp、7 个非零对）。⇒ 报表标"**语料结构使该变量不可测**"，等轨道 B 长文档再测（目前仍不可测）。
7. **参数敏感性**：`fetch_k` 20 → 50 让未召回从 3 涨到 **6**（P95 41 → 61 ms）
   ⇒ **扩大候选池在这份语料上是负收益**：排到后面的材料质量更低，融合权重又把它们推进了 top-5。

## 4. 失败案例归因

判分四个数看不出"为什么错"。`scripts/analyze_ablation_failures.py` 把逐题结果拆成**两类可复算判据**
（每类都是一个能报计数的判据，不是形容词）。**2026-09-21 收敛：F3/F4/F5 已移除，只留 F1/F2。**

| 类别 | 判据 | 基线@300 | 精排@300 | 向量@300 | 基线@100 | 精排@100 |
|---|---|---|---|---|---|---|
| **F1 未召回** | `hit@k = 0`，gold 没进 top-5 | 3 | **1** | **16** | 3 | **1** |
| **F2 召回未居首** | `hit@k = 1 且 mrr < 1` | **13** | **0** | 3 | 6 | **0** |
| **F3 字面歧义** | F1 里检回的首篇**也含同一答案 span** | 0 / 3 | — | — | 0 / 3 | — |
| **F4 组件引入 / 修好** | 只本臂 F1 / 只本臂对 | — | 0 / **2** | **13** / 0 | — | 0 / 2 |
| **F5 拒答无信号** | 库外题仍返回 ≥1 篇材料 | **90 / 90** | 90 / 90 | 90 / 90 | 30 / 30 | 30 / 30 |

> ⚠️ **F3 / F4 / F5 这三行是 2026-09 的历史口径**（当时脚本还算这五类）。
> 2026-09-21 起 `scripts/analyze_ablation_failures.py` 只算 F1 / F2
> （F3 依赖把整份语料读进内存做子串扫描、结论不可复算；F4 是配对计数不是失败模式；
> F5 在本题集样本恒为 0）—— 今天跑那条命令**产不出这三行的数**。
> 数字保留是为了让"当初为什么删掉它们"可查，不代表现在还有这个判据。

**四条判断**

1. **排序失败是召回失败的 4.3 倍**（F2 13 vs F1 3）⇒ 这就是 D13 把主判指标换成 nDCG/MRR 的全部理由：
   基线已经把 98.6% 的 gold 捞进 top-5，还能优化的只剩"摆到前面"。用 Recall@5 当主指标，
   等于拿一个只剩 3 道题空间的量表去分辨组件优劣。
2. **精排的 +3.66pp 逐题可解释**：F2 13 → **0**、F1 3 → 1、只本臂对 2 道、只本臂失 **0** 道。
   13 + 2 = **15 = Wilcoxon 的非零对数**，且全部同号 ⇒ 那条 p=0.000473 不是分布尾巴上的噪声。
   **效应量、机制、显著性三者对齐的，全矩阵只有这一条。**
3. **基线残留的 F1 里 2/3 是"问句没有字面锚点"**：F3 判据先排除了"检回另一篇同答案文档"这种解释（0/3），
   剩下的是 ——
   `A-factual-077`「**它们**以什么为食？」（gold 答案 span 全库唯一，却没进 top-5）、
   `A-factual-093`「**这本书**有什么参考价值？」（同样全库唯一）、
   `A-factual-001`「袭击渔船的生物是谁？」（答案见于 3 篇）。
   前两道是 **CMRC 的篇章内指代**：脱离所属篇章就没有可匹配的词 ⇒ **检索层无解**，
   只有 query rewrite（补指代）能吃这类题。这也解释了 §6 那条"扩语料救不动 Recall 地板"。
4. **F5 是最该答辩的一条**：90 道库外题，检索层 **90 道都返回了 4–5 篇材料**
   （87 道满 5 篇，3 道因文档级保序去重把同篇的两块并成一篇而剩 4 篇，如 `A-refusal-216`）。
   "让检索层判断库里有没有"从原理上不成立 ⇒ 拒答必须是生成侧性质（Phase B 的 `B-E4-refusal` 臂测的就是它）。
   任何在检索层做"相关度阈值 = 拒答"的设计，都会被这一列数据否定。

## 5. 统计功效：为什么必须 300 题，以及 300 题够不够

Wilcoxon 双侧检验在只有 `m` 个非零对时，**最小可达 p = 2/2^m**（全部同号已是最好情况）。
42 元 Holm 族要求原始 p < 0.05/42 = **0.00119**：

| 非零对 m | 最小可达 p | 能过 42 元族？ |
|---|---|---|
| 8（n=100 时两条主臂的实测） | 理论 7.8e-03 / 实测 0.0097 | ✗ **不可能** |
| 10 | 2.0e-03 | ✗ |
| **11** | 9.8e-04 | ✓ 临界线 |
| 15（精排@300） | 6.1e-05 | ✓ 实测 0.000473 |
| 16（向量@300） | 3.1e-05 | ✓ 实测 0.000383 |
| 23（BM25@300） | 2.4e-07 | ✓ 但实测 0.4577 ⇒ **真没效应** |

- **墙确实被推开**：`A-E2a-vector` 同一臂、同一判据，校正后 p 从 n=100 的 **0.3958（n.s.）** 变成 n=300 的
  **0.0130 ✓**（原始 p 0.0097 → 0.000383，非零对 8 → 16）；精排从"任何结果都过不了"变成 **0.0199 ✓**。
  代价 **¥0**（Phase A 全是本地模型）。
- **"过不了校正"与"没有效应"从此是两件事** —— 这是本报告最想答辩的方法论点：n=100 时两者混在一起无法区分。
- **小样本的"收益"会被稀释**：`A-SENS-chunk256` 在 n=100 报 +1.05pp / 2 个非零对，n=300 缩到 +0.13pp / 7 对。
  ⇒ 落盘的 `ablation_table.md` 把 **ΔnDCG、原始 p、校正后 p 三列并列**，就是为了防止只读一列。
- **一条省 3.5 小时的判据（写在结果之前）**：原始 p 与族大小无关 ⇒ 两臂趟量出 `p_raw < 0.00119`
  就等价于在完整 42 元族里通过。所以精排只跑了 `A-BASE + A-E3-base`（48 min），没重跑全矩阵。
  ⚠️ 差值有并列时实测 p 会**高于**理论下界（n=100 重排臂 8 对全同号，下界 0.0078、实测 0.0097）⇒ 以 p_raw 为准。
- **还没解决的**：hit@5 的 McNemar 在精排上是 2 胜 0 负但 p_raw=**0.5** ——
  同一批题、同一臂，**Recall 检不出、nDCG/MRR 检得出**。这是 D13 换指标唯一的对照实验背书，
  也说明"天花板检查"和"主判指标"必须是两件事。

## 6. 语料规模与天花板（一条负面结论）

D13 要求"基线 Recall@5 ≤ 0.95 才算语料合格"。实测：**扩题把它顶得更高，扩语料也压不下去。**

| 语料 | Recall@5 | nDCG@5 | nDCG 余量 | 未召回/210 | 术语 nDCG |
|---|---|---|---|---|---|
| 1,000 篇（现行） | 0.9857 | 0.9586 | 4.14pp ✗ | 3 | 0.9573 |
| 2,000 篇 | 0.9762 | 0.9470 | **5.30pp ✓** | 5 | 0.9369 |
| **3,051 篇（CMRC 全量）** | **0.9762** ✗ | 0.9401 | **5.99pp ✓** | 5 | **0.9176** |

三点跑法是**题集一个字不动、只换 `--fixtures`**（把 `3,251 篇全集 − 1,000 入库 − 200 留出 = 2,051 篇`
按 doc-key 补进语料目录），所以三点严格可比。

- **nDCG 那半边判据救得回（2,000 篇就够），Recall 那半边救不回** —— 0.9762 是**地板**：
  残留未召回里 2/3 是 §4-3 那两类无锚点指代题，与语料规模无关；而 3,251 篇就是 CMRC 的全部
  （设计文档原先写"1,200 篇候选"是错的，已复核改掉）。
- **难度配比这个杠杆是零效应**：`--ambiguous-ratio`（事实题里"答案 span 出现在 ≥2 篇"的超采比例）
  0.4 → 0.6 → 0.75，基线 nDCG@5 只有 0.9586 → 0.9604 → 0.9613。
  ⇒ 设计里"超采模糊题给向量/混合臂留区分度"的假设**在本语料规模上被证伪**。
- **加干扰篇唯一的实质好处落在术语列**（0.9573 → 0.9176）—— 恰好是轨道 B 最关心的题型。
- **副作用**：语料拉到 3,051 篇后，现有 90 道拒答题里 **6 道（6.7%）** 答案已字面可得
  （检索不计分所以不影响本表，但会压低 Phase B 的"正确拒答率"）⇒ **不能悄悄换语料**。
- 三条出路（A 只加干扰篇 / B 全量重建 / C 语料 3,000 + 留出 251 重算拒答集）见 §8.15。
  **2026-09-20 已拍 A**（D15）：干扰篇补齐脚本与 6 道脏拒答题的清单已落盘
  （`scripts/build_corpus_a.py` + `evaluation/dataset/refusal_audit_a.json` +
  `corpus_a_manifest.json`，3,051 个 doc-key、指纹 `2b933d331576`；语料目录本身不入库，一条命令再生）。
  新语料上 `A-BASE` 与上表第三行**逐位相同**（300 题 top-5 全等）⇒ 语料补齐已验证。
  **但本文主表仍是 1,000 篇口径**：14 臂复跑跑到精排臂时机器把页面文件打爆
  （`os error 1455`，当时物理内存只剩 0.9 GB / 15.9 GB），**已决定先不重跑**，
  A 口径的主表等内存宽裕那一趟再出。

## 7. 成本与延迟（实测，不是估算）

| 项 | 值 |
|---|---|
| 13 臂 × 300 题整趟 | 35.6 min / **¥0**（runner 预估 1190 s ⇒ **低估 ×1.8**） |
| └ 查询侧 | 13 臂 × 300 题合计 **3.4 min**（融合/分块臂复用基线索引，8.9–16.9 s；两条 torch 臂 24.1 / 60.9 s） |
| └ 索引重建（7 组） | **32 min**，其中 bge-large 一组独占 **1 314.7 s（21.9 min）**、torch-base 319.3 s，fastembed 四组 44.6–75.0 s |
| 精排臂 × 300 题（两臂趟） | **47.1 min** / ¥0（预估 63 min ⇒ 第 5 次校准，首次**估高**） |
| 检索 P95 | fastembed 各臂 29.3–61.0 ms；torch base/large 85.8 / 308.9 ms；**精排 10 523 ms（×255）** |
| 历史：15 臂 × 100 题整趟 | 1h43m / ¥0，其中重排两臂占 76 min |
| 语料探针（2,000 / 3,051 篇基线） | 索引 99 s / 141 s，查询 12.7 / 17.6 s ⇒ **¥0，合计 4 min** |

**排期结论**：**题数几乎不要钱，语料规模与嵌入模型才要钱。**
⇒ 消融矩阵的设计原则是**能复用索引组的臂排在一起**（runner 按 `index_key()` 分组，同组只建一次库；
精排与融合臂都复用基线索引组，所以 §2 里那条精排臂没有多付一次索引钱）。
**估时不可信**这条已经第 5 次出现，方向 4 次低估、1 次估高 ⇒ 常量要每次实跑后回写（`ablation.py` 顶部，单测钉住）。

## 8. 已知局限（主动写，不等被问）

1. **judge 与生成同源**（都是 DeepSeek 家族）⇒ 生成侧四指标存在自偏好风险。
   缓解：judge 温度 0、prompt 固定、指标自实现且有单测钉住"一题恰好 5 次 judge 调用"的成本不变量；
   **未做跨家族互评**。
2. **轨道 A 题目来自公开抽取式数据集**（CMRC2018），问句带篇章内指代（§4-3），
   对检索系统是"偏易 + 少量结构性无解"的混合，**不能外推到开放问答**。
3. **E2b（分块）与 A-DICT（词典）仍不可测** —— 缺轨道 B 的 3–5 份长文档（能源/弱电规程，
   每份 ≥3,000 字带多级标题），50 道轨道 B 题出不了。本文对分块的唯一表述是"不可测"，不是"无影响"。
4. **语料天花板未过**（§6）：基线 Recall@5 有 0.9762 的地板。本文所有检索结论都在
   "命中饱和、排序有余量"的语料上取得，换到长文档语料后需要重测。
5. **生成侧（Phase B）一次都没跑** ⇒ 本文不含 faithfulness / context_recall / 拒答率的任何数字。
   就绪彩排已做完（6 臂准入全过、成本按本地实测重量算出 6 臂 × 300 题 ≈ ¥27 高峰），**只剩 key**。
6. **`A-E3-m3` 缺 300 题数字**（只有 n=100，且与 base 逐位相同 ⇒ 已判可砍，不补）。
7. **没有误差棒**：全部是单次运行的点估计 + 假设检验，**没有 bootstrap 置信区间**。
   确定性已验（同配置两次跑四指标逐位相同；按 query 文本对齐后，n=100 与 n=300 两趟的 100 道共有题
   top-5 顺序**逐条相同**）—— 但"可复现"不等于"有置信区间"。
8. **跨报表对齐只能按 query 文本**：`build_golden_set.py` 的 qid 是全局流水号，改题型配比就会重编号
   （300 题趟与 100 题趟只有 22/100 个 qid 指向同一道题）。内容上 100 题是 300 题的真子集（已补单测钉住）。
